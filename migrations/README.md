# migrations

SQL for the shared uwuapps Supabase project. Paste each file into the SQL
editor and run it once, in number order.

**Never edit a file once it has been run.** Every change, to the schema or
the station data, is a new file with the next number.

| File | What it does |
|---|---|
| `001_mrtguessr_schema.sql` | The `mrtguessr_` tables, the best-per-name leaderboard view, and the rate limit, submit and prune functions. |
| `002_mrtguessr_seed_stations.sql` | The 184 stations. Generated by `python scripts/seed_supabase.py --sql`; regenerate rather than edit. |
| `003_mrtguessr_leaderboard_totals.sql` | The total points board: a view adding up every submitted round per name, and submit returning both ranks. |
| `004_mrtguessr_anti_cheat.sql` | Submit refuses rounds solved in under 3 seconds, and rounds played at the same time as another on the board under the same name. |

`002` and `python scripts/seed_supabase.py` load the same rows; use either.
After refreshing `main-site/data/`, `python scripts/seed_supabase.py --sql`
writes the stations as the next numbered file, leaving `002` as it was.

Every table has row level security on with no policies. Only the service role
key, used by the Vercel functions and the seed script, can read or write.
